# Phase & Bounded Task Execution Matrix

**Purpose:** the single index for every bounded Task across Phase 0–6: outcome, dependencies, owner scope, exact source-test assignment, evidence and stop conditions. This is a work contract, not implementation proof.

## Global contract for every Bound

- One invocation = one bounded Task. Internal edit/test/repair loops are allowed only inside the stated scope. At acceptance or safe blocker, checkpoint, report and stop; do not auto-start another Task.
- Before editing, inspect actual repository/workspace/diff; then read this task row, current canonical owner files, cross-system invariants and its assigned rows from `delivery/10_LEGACY_ACCEPTANCE_TEST_CROSSWALK.md`. Never assume prior commands/files exist.
- A legacy source test is a design input, not a current rule or current test result. Map it to exact current `AC-SYS` / `UI-P1` IDs at the phase gate, or record a reasoned superseded/deferred/duplicate/blocked disposition.
- PASS requires real output/evidence with build/config/workspace fingerprint. A test file, specification, plan, source label or attractive screen is not a passing test.
- No live DB mutation, destructive migration, secrets change, publication/deploy, payment activation or irreversible asset/data change without a task-scoped verified isolated target and permission.
- Record changes to game rules in the owning system file and reconciliation log. Do not create duplicate rule sources.
- On interruption, persist last verified criterion, first incomplete criterion, changed files, actual test output and next safe action. Resume from observed files/diffs, not hidden analysis.

## Required phase-entry gates

`P2-GATE-000` through `P6-GATE-000` must finish before that phase implementation begins. Each gate performs the phase-specific source/semantic audit, checks every assigned legacy test row against active owner rules, links exact current criteria, builds the test plan and records dispositions. This keeps unresolved future-phase details from silently reaching code without forcing unrelated Phase 1 work to stop.
