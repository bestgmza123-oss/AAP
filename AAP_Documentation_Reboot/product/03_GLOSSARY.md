# Glossary

| Term | Meaning in AAP |
|---|---|
| Account | Login identity and account-level data/balances. Survives Character death. |
| Character | The playable survivor. Only one active Character per Account; death is permanent for play. |
| Province | A world hub/location containing services and access to local Districts. |
| District / Dungeon | A selected exploration area that starts one bounded Run. |
| Run | One finite dungeon attempt with a persisted timer, enemies, combat, pending rewards and a terminal result. |
| Hunger | Player-facing name for the old Satiety meter. Baseline: 100 = fed; 0 = death. This label change does not reverse the meter. |
| Infection | A harmful resource increased only by eligible infectious actions that cause positive HP damage. |
| Stamina | Resource for travel and dungeon entry. Does not regenerate during a dungeon Run. |
| Mana | Resource used by skills. Regeneration is Province-only under the current baseline. |
| Scrap | Material/resource obtained during exploration and used in crafting/salvage/trade. |
| Loot pending | Rewards accrued but not yet transferred into permanent inventory until valid selection/commit. |
| Character-bound | Owned by a specific Character and governed by Character-death disposition. |
| Account-owned | Owned by Account; may survive Character death according to its named rule. |
| Escrow | Assets temporarily held by a transaction/listing lifecycle so they cannot be simultaneously used elsewhere. |
| Recovery Locker | Durable claim location for Companion mission cargo and other explicitly designated recovered assets. |
| Simulation | Isolated Association/Tower combat with its own session/attempt clock; does not rewind world time. |
| AI-DEC | AI-selected design default under past delegation; not automatically owner-confirmed and not runtime proof. |
| Owner-confirmed | A rule explicitly confirmed by the owner for the stated scope. Do not overextend that confirmation. |
| Fixture | Synthetic, non-final content used to test a system or prototype. Must be visibly labelled. |
| UI-Driven | The interface itself is the play space; layout, flow, interaction, accessibility and clarity are part of feature acceptance. |
| Vertical Slice | A small, complete playable loop proving connected systems rather than a collection of isolated screens. |
| Design complete | Current behavior has a written decision. Does not mean implemented, tested or balanced. |
| Runtime verified | The behavior has been tested in the real target environment with inspected evidence. |
